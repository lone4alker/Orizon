# ENT-Monitor: Analysis Layer Architecture

The Analysis Layer is a multi-agent orchestrated pipeline built using LangGraph. Its primary goal is to take a batch of raw social media posts that have passed the initial semantic filter and systematically group, research, classify, and persist them into trackable health trends, while aggressively filtering out noise.

Here is exactly how the pipeline works **now**, including all recent updates to thresholding and ENT-specific gating.

---

## 1. OBSERVE: Clustering & Scope Gating
The pipeline begins in `layers/analysis/nodes/observe.py` by attempting to group hundreds of posts into meaningful behavioral trends.

1. **Mathematical Clustering (`observe.py` lines ~115-125)**: 
   The system uses the `UMAP` library (reduced to 8 dimensions for stability) and `HDBSCAN` (with `min_cluster_size=5`). Any group of posts smaller than 5, or any post that doesn't fit densely into a math cluster, is labeled by HDBSCAN as cluster `-1` (noise). The python code automatically moves these into a python list called `noise_posts`.

2. **AI Validation & Ejection (`observe.py` lines ~460-500)**: 
   The python code loops over each dense cluster and sends it to the LLM. 
   - **How the AI controls the code**: The AI does not give commands. It uses Langchain Structured Output to return a strict Pydantic JSON object called `ClusterValidation`. 
   - This object contains a boolean field `is_ent_related` and an array field `split_post_ids`. 
   - **ENT Scope Gate**: If the AI determines the cluster is out of scope, it returns `is_ent_related: false`. 
   - The python code reads this JSON. If it sees `false`, or if it sees specific post IDs in the `split_post_ids` array, the python code physically `pop()`s those posts out of the cluster and appends them to the `noise_posts` list.

3. **Noise Sweep (The Safety Net) (`observe.py` lines ~517-580)**: 
   You asked: *"what if there is a post that forms a cluster with 2 other posts which doesnt pass the 5 post threshold but it is high in severity... we cant just toss posts aside."*
   This is exactly why the Noise Sweep exists! Because HDBSCAN throws away anything smaller than 5 posts, those 2-3 dangerous posts end up in the `noise_posts` list.
   - The python code takes **all** posts in `noise_posts` and sends them in a single, large bulk prompt (`_UNCLASSIFIED_PROMPT`) to the LLM. 
   - **Is it expensive?** Yes, it uses a large context window, but because it sends all noise posts in one single API call, it prevents having to loop the LLM hundreds of times.
   - The LLM returns a Pydantic object called `UnclassifiedValidation`, which contains an array called `new_groups`. If the LLM spots those 3 highly dangerous "Nyquil chicken" posts in the noise, it puts their IDs into a `new_group`. 
   - The python code reads this JSON and creates a brand new cluster (`cluster_new_X`) for those 3 posts, completely bypassing the HDBSCAN math limits! 
   - Any post left completely unassigned by the LLM after this single bulk sweep is permanently discarded (marked as `LOW` in the DB via `write_safe_posts_to_db`).

## 2. RESEARCH & ASSESS: Evidence Gathering
For every valid ENT cluster that survived the `OBSERVE` step, the system must find clinical backing.

1. **Research Node**: The AI generates medical search queries and hits multiple APIs (PubMed, DuckDuckGo, Semantic Scholar, Crossref).
2. **Assess Node**: The system calculates a deterministic "Evidence Quality Score." The cluster must achieve a score of `> 0.45` to proceed. If it fails, the pipeline commands the Research node to try again with different queries (up to 3 retries).

## 3. CLASSIFY: Severity & Thresholds
Once evidence is gathered, the AI acts as a senior medical analyst.

1. **Severity Rating**: The AI rates the behavior as `HIGH`, `MODERATE`, or `LOW` risk based strictly on the gathered clinical evidence.
2. **Secondary Scope Gate**: As a backup, the system prompt forces the AI to flag the cluster as `out_of_scope = True` (and force a `LOW` rating) if the core behavior doesn't involve ENT anatomy.
3. **Trend Threshold & Lifecycle**:
   - The AI checks if the cluster has at least **5 posts** and spans at least **2 platforms**.
   - If it meets this threshold, it gets a trend lifecycle (e.g., `Emergence`, `Growth`, `Latent`).
   - If it fails the threshold, it is labeled an **`Isolated incident`**.

## 4. VERIFY: Hallucination Check
A separate, hyper-strict LLM node reviews the output from the `CLASSIFY` step. It ensures that the cited evidence actually supports the severity rating and that the AI did not hallucinate medical claims.

## 5. DECIDE: Routing & Noise Filtering
This is a deterministic (Python logic, no AI) router that decides the ultimate fate of the cluster.

1. **The Noise Filter**: The system looks at the labels generated by `CLASSIFY`. 
   - If the cluster is `LOW` severity **AND** it is either an `Isolated incident` (failed the size threshold) or `out_of_scope`, the router **throws it in the trash**. It marks the posts as `SAFE` so they aren't re-processed, but refuses to write the cluster to the `trends` dashboard.
2. **Velocity Monitor**: If a cluster is `HIGH` or `MODERATE` severity, it is flagged (`should_monitor = True`) to be picked up by the high-frequency velocity monitor.

## 6. REPORT
If a cluster survives all gates and the `DECIDE` router approves it for the database, it passes to the `REPORT` node. A fast LLM model generates a clean, structured Markdown summary of the trend and its harm mechanisms, which is then finally persisted to the database and displayed on your dashboard.
